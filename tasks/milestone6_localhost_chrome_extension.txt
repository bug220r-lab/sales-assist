# Hard security boundary

The manifest may contain host permissions only for:

```text
http://127.0.0.1/*
http://localhost/*
```

No wildcard internet permission.

Prohibit:

- `cookies`
- `webRequest`
- `webRequestBlocking`
- `nativeMessaging`
- `debugger`
- `downloads`
- `clipboardWrite`
- broad `tabs` unless independently justified
- remote code
- `eval`
- external scripts/assets
- generic click/type/fill/keyboard/submit helpers
- mutation of source facts
- production domains/selectors
- arbitrary URL fetch
- credential/session access.

Use static content-script matching where possible. Request only the minimum permissions needed
for the side panel and local extension state.

Create a manifest/permission ADR and exhaustive permission test.

# 2. Supported pages and origin validation

Support only the M5 synthetic portal page kinds required for evaluation:

- synthetic order detail;
- synthetic interaction detail where Sales Credit evaluation needs it;
- optional scenario page convenience behavior.

Before extraction:

1. verify page origin is loopback and matches allowed service origin policy;
2. verify `data-ssa-page-kind`;
3. verify DOM contract version;
4. verify schema version;
5. verify synthetic identity;
6. verify required sections;
7. verify completeness state;
8. verify declared/rendered line counts;
9. verify ordered line-manifest digest;
10. compare allowlisted DOM facts with embedded canonical payload.

Unsupported, mismatched, incomplete, or malformed pages fail closed.

Do not run on unrelated localhost pages merely because the host matches.

# 3. Allowlists and extraction

Implement an explicit versioned extraction allowlist.

Order extraction may read only governed fields such as:

- synthetic order ID;
- status;
- timestamps;
- completeness facts;
- line identity;
- canonical fictional product IDs;
- quantity;
- exact price/currency;
- availability;
- ETA;
- DS state;
- activity;
- structured fictional interactions/observations required by the scenario.

Sales Credit extraction may read only the governed fictional interaction fields.

Prohibit:

- arbitrary page text;
- `innerHTML` transfer;
- unrestricted notes;
- script source;
- browser storage;
- cookies;
- hidden unrelated DOM;
- file paths;
- query strings not in the closed contract.

Return a closed versioned extraction object.

# 4. Independent completeness/coherence verification

- requested/observed order identity;
- rendered line identities;
- declared/rendered counts;
- duplicate lines;
- ordered manifest;
- source time;
- DOM/payload equality;
- completeness status;
- schema/version.

If the page says COMPLETE but the extension detects a mismatch:

- do not evaluate;
- display a fail-closed discrepancy;
- make no successful API call;
- persist no successful evaluation.

Add tests for every M5 malformed mode.

# 6. Evaluation request

The extension sends only the closed extracted facts to the loopback API.

The committed M5 service origin is:

```text
http://127.0.0.1:8765/
```

The extension may also accept `localhost` only through the documented closed loopback-origin
normalizer. It must reject every non-loopback host, alternate scheme, credentials-in-URL,
query-injected origin, and arbitrary port unless the committed local configuration contract
explicitly authorizes that bounded port.

Requirements:

- explicit user click to evaluate;
- bounded request key;
- no evaluation on page load;
- no repeated hidden polling;
- no external fetch;
- exact replay support;
- conflict display;
- request/response version checks;
- abort/timeout behavior;
- safe retry;
- backend unhealthy blocks evaluation.

The extension may open the local portal/dashboard in a new tab, but may not navigate or interact
with source controls generically.
