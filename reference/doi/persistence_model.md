# Synthetic Sales Assist DOI v0.1.5 — Persistence Model

Status: independent-audit remediation candidate; independent re-audit required; specification only.

This artifact makes the remediated persistence identities, histories, uniqueness constraints, and purge edges explicit. It authorizes no live Synthetic Order Portal access or production implementation. Synthetic Order Portal remains permanently read-only.

## 1. Normative composition

This persistence model incorporates, without paraphrase loss, five governing package modules/registries:

1. `source_retention_contract.md` — exact locked source mapping, batch identity, import attempt, run outcome, no-case rejection retention, ISO Money, `calendar90`, and observation deletion;
2. `provenance_state_contract.md` — canonical event envelope, evaluation bindings, relationship revisions, Action Context, typed histories, reducers, and purge graph; and
3. `opportunity_kpi_contract.md` — immutable credit scope/overlap/option identity, evidence natural keys/fingerprints, result-link revisions, retained KPI contributions, daily buckets, upsert, and atomic finalization;
4. `DOI_LIFECYCLE_EVENT_PAYLOAD_REGISTRY_v0.1.5.md` — the closed lifecycle event envelope and event-kind payload union, null/absent partitions, reducers, canonical bytes, and hashes; and
5. `DOI_OA_CAPABILITY_POLICY_v0.1.5.md` — the closed offline manifest/module/browser capability surface and structural safety scan.

The detailed field tables, canonical serialization inputs, hash domains, uniqueness constraints, predecessor rules, reducer algorithms, and purge edges in those modules are part of this persistence model. The technical specification and machine contract provide the business/entity overview; a looser legacy clause cannot override an exact module schema.

All append-only records use RFC 8785 canonical UTF-8 serialization and lowercase SHA-256, with the domain/version named by the governing module. Canonical bytes required for collision comparison survive only while their case/source-retention graph survives. Projections are rebuildable caches; immutable events/facts are authoritative.

## 2. Persistence topology

| Layer | Authoritative records | Rebuildable projections | Retention boundary |
|---|---|---|---|
| Source invocation | v2 `DOIRunEvent`, v2 `DOISourceImportAttemptEvent`; transaction-local `DOISourceImportAttemptRetentionEventV1` | terminal run/import-attempt fields and exact joined deadline | every terminal attempt outcome and run identity at `calendar90(run.completed_at)` subject only to explicit last-owner retention; no detail is exempt; retention event deletes in its own transaction |
| Coherent personal source | retained `DOISourceBatch`, explicit `DOISourceBatchReference`, attempt-owned staged TARGET_REP records, case-owned `DOICaseSourceBinding`/`DOICaseSourceAdmissionProofV1` | batch lookup while at least one owner survives | each reference deletes with its owner; TR-113 deletes the complete identifying batch/fingerprints at the exact last reference; TR-114 deletes staged/attempt detail; only aggregate v2 month/outcome/count survives |
| Source facts | `DOIExtractionAttempt`, immutable snapshot and lines | current snapshot pointer | case purge |
| Human facts | typed `DOIHumanFactEvent`, contact/DEDUPE decisions, link confirmations | current typed projections | case purge |
| Evaluation outputs | immutable `DOIEvaluation`, immutable `DOIOpportunity`; an already accepted observation ID/hash binding becomes a sealed non-resolvable historical commitment if its volatile target expires | current evaluation/opportunity views, but an expired target can never satisfy current-action freshness | case purge |
| Lifecycle/action | `DOIOrderLifecycleEventV2` core case projection ledger plus two target-owned volatile observation/link wrapper streams and dedicated Action Context, attention v2, WWC, intervention, link, and value/reversal fact streams | exact `DOIOrderCaseProjectionV2` plus typed current projections | core at case purge; volatile wrappers atomically with target at earlier observation/case deadline |
| Reusable product knowledge | stable alternate relationship plus immutable revisions | current revision projection | indefinite only when product-only from inception and fully de-linked |
| Volatile alternate facts | immutable alternate observation and context link plus their one-event volatile lifecycle wrappers | current-for-context view | all target/wrapper bytes delete atomically at earlier of nominal `calendar90(observed_at)` and linked-case purge |
| Realized KPI detail | immutable intervention ledger plus `DOIRetainedKPIContribution` | retained contribution | transfers/deletes atomically at case purge |
| Aggregate KPI | `DOIAggregateKPIDailyBucket` leaf rows | computed rollups | durable non-identifying aggregate only |

Source facts, human facts, evaluation outputs, and lifecycle events are different record classes. No API, reducer, or migration may store one as another or overwrite a prior record.

## 3. Required identities and constraints

### 3.1 Source/run

- One accepted `RUN_DOI_REVIEW` invocation creates one run and ordinal-1 source-import attempt before acquisition. One or more sequential attempts are legal under the closed pre-OA retry rule; enforce `UNIQUE(run_id,attempt_ordinal)` and `UNIQUE(run_id,attempt_command_token_sha256)`. Attempt IDs are opaque/non-derived and all token/ordinal indexes delete under TR-114.
- `DOISourceBatch.source_batch_identity_sha256` is unique and binds spreadsheet ID, exact tab role/title/gid, schema version, TARGET_REP-row-content hash, and assignee-conflict fingerprint. Same digest requires byte-identical canonical identity material.
- Invocation counts, actor/time, physical locators, source-change diagnostics, and rejected identities are forbidden batch fields.
- Every retained batch has at least one exact `DOISourceBatchReference` with a foreign key to one closed owner type: RUN, SOURCE_IMPORT_ATTEMPT, STAGED_SOURCE_RECORD, NO_CASE_REJECTED_RECORD, or CASE_SOURCE_BINDING. Its ID is the exact domain-separated hash of the closed batch/owner tuple in `source_retention_contract.md` section 2.4; resolve and byte-compare before assigning `created_at`. Enforce unique `(source_batch_id,reference_owner_type,reference_owner_id)`, exact identity/canonical bytes/hash, and deletion/cascade with the owner. `DOICaseSourceBinding` uses its separate exact deterministic case/batch identity. No event or indirect pointer creates an undocumented lifetime.
- A `SOURCE_IMPORT_ATTEMPT` batch reference and coherent fingerprint exist only for `SUCCEEDED`. For `SCHEMA_REJECTED`, `SOURCE_CHANGED`, `INACCESSIBLE_OR_UNREADABLE`, `BATCH_INTEGRITY_REJECTED`, and intermediate `ABORTED_PRE_OA`, both are null and no batch reference exists. RC-090+specific code applies only to the four failed classes; aborted uses its separate empty-reason event and requires a later ordinal before run terminal.
- TR-113 evaluates `NOT EXISTS` references after all due owner releases under a batch/reference lock. False retains the unchanged batch; true deletes the complete batch ID/identity/TARGET_REP/conflict fingerprints/counts and every batch-identifying event/cache/log/export in the same transaction. No batch hash/tombstone/receipt survives; only `DOISourceImportAggregateV2 {aggregate_schema_version,local_calendar_month,attempt_outcome_class,attempt_count}` survives. It has no ID/hash/reason/drill-through or extra member. TR-114 exclusively owns the per-attempt aggregate increment; a later independently invoked TR-113 preserves it and applies zero delta. Any failure rolls back the full owner/reference/batch transaction and any aggregate delta owned by a same-transaction TR-114 caller.
- Every `DOIStagedOrder` is READY-only and attempt-local with required `run_id`, required `source_import_attempt_id`, and the safely bound `source_batch_id`; enforce `UNIQUE(source_import_attempt_id,order_number)` (not run/order, because a legal later ordinal is distinct). It stores literal `doi-staged-order/v1`, immutable `created_at`, and the exact closed full-record `record_content_sha256` from the machine contract. `DOISourceBatch` likewise stores literal `doi-source-batch/v1` and its exact full-record digest from the source contract; a terminal `DOIExtractionAttempt` stores literal `doi-extraction-attempt/v1`, immutable `completed_at`, and its exact full-record digest. The attempt must belong to that run and bind that batch. Source refs/locators are current-attempt facts and are never reused from an immutable batch. Under `synthetic-doi-queue-v0.1`, duplicate TARGET_REP rows always merge with RC-006 and E:O is ignored; RC-007 is compatibility-reserved/unreachable. Only a same-number TARGET_REP plus nonblank non-TARGET_REP scalar assignee conflict creates no staged order/work item and instead owns one attempt-local RC-008 `DOIRejectedSourceRecord` plus retention-schedule event; its v2 natural identity is `(source_import_attempt_id,order_number)`. Blank scalar B is not a conflict. TR-105/TR-114 atomically remove the rejection graph.
- Every staged record and TARGET_REP source reference remains attempt-owned and deletes under TR-114; none transfers into a case graph. Before `CASE_CREATED` or manager-origin `SOURCE_PRESENT`, create/reuse one exact case-owned `DOICaseSourceAdmissionProofV1` plus `DOICaseSourceBinding`. The proof binds case/Order Number/TARGET_REP/batch/case-binding/time/hash but contains no run/attempt/ordinal/token/row/tab/actor detail. Lifecycle binds this proof, so attempt deletion leaves no dangling target.
- `DOIRunOrderWorkItem` persists one explicit nullable `source_batch_id`. It equals the staged order's batch for manager-origin work and the coherent selected manager batch for source-absence verification; other work uses explicit null unless it reuses the retained snapshot's producing work item. `origin` and `source_batch_id` are write-once immutable, every attempt/snapshot/evaluation chain uses non-null retained foreign keys, and those owners delete together at the governing graph boundary. Lifecycle source wrappers derive the batch through `extraction_attempt -> run_work_item`, `snapshot -> extraction_attempt -> run_work_item`, and `evaluation -> snapshot -> extraction_attempt -> run_work_item`. Missing or disagreeing links reject with RC-113; extraction, snapshot, and evaluation do not invent duplicate batch fields.
- Every non-success import has null `source_batch_id`; it has zero work/cases/evaluations/OA reads. Every terminal outcome receives `source_import_attempt_purge_eligible_at=calendar90(run.completed_at)` only when the associated run later terminalizes; while run is nonterminal the deadline is null.
- Persist one exact `DOIRunIdentityReferenceV1` for every retained attempt, staged record, no-case rejection, and `RUN_WORK_GRAPH` that lawfully needs `run_id`. The work owner exists only while a retained extraction/snapshot/evaluation chain must resolve its exact run work item and uses that graph's case/work deadline. `DOICaseSourceBinding`/admission proof contain no run ID and own no run reference; their separate source-batch ownership is unaffected. `DOIRunEventV2`/run projection contain attempt count only, never an attempt ID/manifest. When the run deadline is due, delete the full run graph only after the locked `NOT EXISTS` predicate over these references is true; any non-due retained owner prevents premature deletion and final-owner deletion removes run identity atomically.
- A rejected/no-case exact identity is unique only within its run-local record and must carry immutable `purge_eligible_at=calendar90(run.completed_at)`. Batch reuse cannot update it.

### 3.2 Evaluation and reusable knowledge

- Every evaluation stores exact snapshot/version/hash, rules/reason/calendar version/hash as applicable, relationship revision IDs/hashes, Action-Context-bound observation IDs/hashes, structured human-fact IDs/hashes, input/output/full-record digests, and exact evaluation time.
- Every evaluation resolves and byte-validates all observation bindings at append. If a bound observation later reaches its earlier governed deletion deadline, the target/link/volatile-wrapper graph deletes while the immutable evaluation/opportunity retains only its preexisting sealed observation ID/hash commitment. That commitment cannot resolve the target, be used as freshness, or enter a new evaluation; it deletes with the case graph.
- Every immutable opportunity stores target field `opportunity_schema_version="doi-opportunity-record/v1"`, immutable `created_at`, every governing opportunity field exactly once, and the registry-defined full-record `record_content_sha256`. The lifecycle payload's generic `record_schema_version` copies that target field. Its lifecycle natural identity binds exact evaluation ID plus scenario option ID; exact bytes reuse one record/time/event and changed bytes fail closed.
- Relationship identity is stable and product-only. `UNIQUE(alternate_relationship_id, revision_number)` and exact predecessor/hash guards enforce monotonically increasing immutable revisions. Terminal superseded/invalidated state cannot reactivate.
- A current observation used for action has one exact OPEN Action Context link compatible with its case/evaluation/opportunity/relationship revision. Closed/wrong-scope links fail.

### 3.3 Opportunities and evidence

- DEDUPE HumanFact kinds include only the two exact decision pairs in `provenance_state_contract.md`. Persist deterministic `dedupe_review_id`, closed decision payload/evidence fingerprint, human command token, and exact immutable verification reference. Human `DOIDedupeStateEvent` rows require a deferred exact FK to the accepted HumanFact ID and full-event hash. Enforce `UNIQUE(case_id,dedupe_review_id,evidence_fingerprint)`, one current decision chain per review, exact byte comparison, and atomic TR-061/TR-062 fact+state-event+lifecycle+projection commit. The sole same-review cross-kind correction is predecessor-bound approval-to-rejection before OA verification; every other conflict is RC-112. An OA note is never a human-fact source.
- Attention v2 persists complete cause and resolution groups on immutable event rows. Enforce unique SET `(case_id,operation,cause_key)`, unique CLEAR `(case_id,clears_attention_event_id)`, active-SET FK, copied-cause byte equality, complete resolver FK/hash/revision/time, and stream-position guard. The active map is rebuildable only; exact replay reuses the accepted row and conflicting CLEAR identity is RC-081.

- Every opportunity has a nonempty exact quantity-bearing `credit_scope`, recomputable `credit_scope_hash`, one candidate-specific `scenario_overlap_key`, and one `scenario_option_id`; `UNIQUE(evaluation_id, scenario_option_id)`. The key must equal `derive_overlap_key_for_candidate(evaluation_id,scenario_basis,credit_scope_hash)` for the exact connected component, not one global key for all same-basis candidates.
- Same-order membership does not create overlap. Actual shared scoped merchandise under one scenario basis does. A multi-option overlap group accepts at most one selected option for calculation.
- `DOILogicalEvidenceKey` is unique on `(case_id, logical_event_kind, natural_key_fingerprint)` and retains canonical key/material bytes until purge.
- ACTION occurrence allocation additionally enforces `UNIQUE(case_id,action_occurrence_id)` before natural-key allocation. Original-value/correction/reversal/correction/void kinds share `UNIQUE(case_id,intervention_id,logical_occurrence_id)`. Cross-natural or cross-kind occurrence reuse and changed material route RC-102 without a second effect; stream predecessor conflicts route RC-111 first.
- `DOIVerificationEvidenceRecord` is unique on `(case_id, event_kind, evidence_fingerprint)` and retains canonical evidence bytes until purge.
- Identical digest plus identical bytes is idempotent. Same natural key with contradictory material effect is a fail-closed conflict. Same digest with different bytes is a fatal integrity failure.
- Exact resulting-order link identity is unique on `(parent_case_id, relationship_type, child_order_number)`; moved-line/quantity mapping has a separate immutable revision/fingerprint. Contradiction sets review and contributes zero disputed credit.

### 3.4 Money and KPI

- Money is exact `{amount_decimal,currency_code,iso_4217_registry_version}`. Arithmetic uses arbitrary-precision integer coefficients at the exact registry scale. No binary float, rounding/truncation, inferred FX, base currency, or mixed-currency scalar is legal.
- `DOIRetainedKPIContribution` is unique on `(kpi_schema_version, intervention_id)` and on deterministic `retained_kpi_contribution_id=SHA256("doi-retained-kpi-contribution-id/v1\n" || JCS({retained_kpi_contribution_id_schema_version,kpi_schema_version,intervention_id}))`, with stored canonical bytes and collision comparison. It immutably stores both `currency_code` and `iso_4217_registry_version`. It exists only when exact business `action_occurred_at` is non-null; required evidence/proof time cannot substitute. Attribution date is immutable from that exact action instant in `America/New_York`; later evidence updates that same date. Currency/registry or first-action-provenance change fails closed.
- `DOIAggregateKPIDailyBucket` is unique on `(kpi_schema_version, LOCAL_CALENDAR_DAY, America/New_York, local_date, currency_code, iso_4217_registry_version, intervention_type, action_provenance)`. UTC boundaries are derived from local midnights and may span 23/24/25 hours; registry versions/scales never collide or silently rescale.
- Weekly/monthly/quarterly/yearly and `ALL` rows are prohibited persisted source-of-truth buckets; they are query rollups.
- Retained-ledger upsert and purge finalization use row locks/serializable equivalent, full-ledger recomputation, immutable identity checks, and one ACID transaction.
- TR-106 persists no ambiguous operational-zero marker. Credit-bearing unverified always has RC-063. Let `B` be the exact date/currency base: exact date with valid or absent currency gives `{RC-063}`; exact date with invalid supplied binding gives `{RC-063,RC-094}` and persists no Money/row; null business action time with valid or absent currency gives `{RC-063,RC-099}` and no row/bucket; null time with invalid supplied binding gives `{RC-063,RC-094,RC-099}` and no Money/row. Union at most one exact rep-proof modifier: a verified split with exact child link whose resulting-order-level TARGET_REP rep is missing/different/ambiguous adds RC-074 only; a substitution with exact replacement-line binding whose line-level TARGET_REP rep is missing/different/ambiguous adds RC-075 only; verified rep adds neither. Wrong-type, contradictory, or both-code input is RC-081 before append. Rep failure preserves the independently valid action, link/binding, and the base-governed count/value/money result; where the base row exists it remains one count-1, zero-money, `UNVERIFIED` row. DS is `NOT_APPLICABLE`, all money/currency null, no row, and none of RC-063/074/075/099 is emitted merely because it needs no monetary attribution or rep proof.

## 4. Common immutable event envelope

Non-case and dedicated typed fact streams store their entity-specific ID alias plus the exact closed envelope and payload defined by their governing source/provenance module. Sequence 1 has null predecessors; later appends name the exact current predecessor. A stale sequence/predecessor or same event identity with different canonical bytes is rejected with `EVENT_STREAM_SEQUENCE_CONFLICT`; the last valid projection remains authoritative. This generic sentence does not define or relax a case-lifecycle payload.

Typed streams exist for v2 run invocation/terminal, v2 source-import attempt start/terminal, transaction-local attempt retention, rejected-source retention scheduling, relationship revision, Action Context, human facts, contact, DEDUPE, attention, WWC, resulting-order links, intervention action verification, and value/correction/reversal. The exact closed run/import/retention event types, payloads, domains, constraints, reducers, and atomicity rules are `source_retention_contract.md` sections 3.4, 4, and 13. The attempt-retention stream is separate, sequence 1/null predecessors, and deleted before its TR-114 commit. The core case lifecycle stream stores case lifecycle facts plus references/digests to retained typed events; two separate one-event volatile streams wrap observation/link record creation without entering the core chain or changing its projection.

`DOIOrderLifecycleEvent` is excluded from the generic envelope above. It uses only `DOIOrderLifecycleEventV2` and literal `event_schema_version="doi-order-lifecycle-event/v2"` from `DOI_LIFECYCLE_EVENT_PAYLOAD_REGISTRY_v0.1.5.md`. Its former v1 `schema_version`/`event_type`/single-source/open-payload representation is not a compatible input. The registry's 56-kind discriminator selects one of eight persisted closed payload schemas, with exact required/non-null/null/absent partitions and exact JCS/domain hashes.

Persist `UNIQUE(lifecycle_event_id)`, `UNIQUE(stream_id,stream_sequence)`, and `UNIQUE(case_id,event_natural_key_sha256)` plus the canonical natural-key bytes. Core sequence 1 is case creation and produces revision 1; later core rows require `result_case_revision=prior_case_revision+1=stream_sequence`, exact prior event ID/full hash, and exact prior projection hash. The two volatile event kinds instead have one event in each record-owned stream, null predecessors, and identical locked non-null prior/result core revision/hash. Typed event or record ID/schema/full hash, lifecycle actor/provenance/time/reasons, and source bindings are cross-checked before one atomic authority/wrapper/projection-or-no-op commit. Exact replay returns the original bytes and allocates nothing. Unknown kind/version/payload, missing/extra field, bad null partition, bad binding, or natural/payload/projection/full hash mismatch uses RC-113 and changes no projection; RC-111/103/081 retain their distinct stream/collision/state meanings. At observation/link expiry, target and volatile wrapper delete together, so no retained missing-source exception exists.

Persist the complete canonical payload bytes for `CASE_REOPENED` and `PURGE_CANCELED`, including their required nested `PriorClosureRetentionBindingV1`; do not normalize that object into a hash-only pointer or reconstruct it on read. The nested object has literal version `doi-prior-closure-retention-binding/v1` and exact non-null columns/serialized members for prior closure event ID/full hash, closed kind/classification, verified instant, policy ID/version, timezone/tzdb/local-calendar rule, active deadline, closure-bearing projection revision/hash, and prior closure source type/ID/schema/full hash. The reopen row additionally stores exact reopen proof type/ID/schema/hash, reason/time, deadline-clear effect, same-case flag, and result revision/hash. The cancellation row additionally stores exact canceled deadline, reopen cause ID/hash, resolution proof type/ID/schema/hash, result deadline state/null deadline, same-case flag, and result revision/hash. Every unlisted/extension member is forbidden.

Under TR-014, lock the case core head, referenced last applicable reversible closure event, its proof target, the retained policy target, the exact closure-bearing projection revision/hash, and the reopen proof before allocation. Foreign-key and byte guards require every nested field to equal those authorities, with `prior_closure_projection_revision/hash` equal to the pre-reopen envelope prior values and `prior_purge_eligible_at` equal to its active deadline. Construct the authoritative object, serialize under RFC 8785, and compare bytes. The following cancellation event has an FK to the exact reopen event; its complete nested binding equals the reopen bytes, its cause aliases equal the reopen ID/hash, its resolution group equals the reopen proof, and its canceled deadline equals the nested active deadline. It then independently repeats the authoritative closure/proof/policy/projection checks. No constraint may be satisfied by resolving only the projection or event hash.

The accepted reopen and cancellation, both payload hashes/full-event hashes, both projection revisions/hashes, and the projection update are one ACID transaction. A missing authority, unknown binding version, field/byte/hash disagreement, unique/FK failure, or injected persistence failure rolls back all rows and retains the prior closed projection/head/deadline byte-identically. Replay resolves and checks the same retained authorities, reproduces the exact same canonical events and ACTIVE/null-deadline projection, and allocates no new ID/time/row. Fixed lifecycle serialization vectors use only reserved synthetic case identities (`SYN-DOI-CASE-0001`, `...0002`, `...0003`); V3's explicitly opaque predecessor/source digests are not a persistence/reachability oracle, while `SYN-LIFE-PAYLOAD-010` separately persists actual closed-schema targets and computes/validates their real hashes. The V1 harness maps `SYN-DOI-ORDER-0001` outside persisted bytes to schema-valid nonhistorical sentinel OrderNumber `"1"`. A non-prefixed executable case fixture or unregistered production-looking/historical order fixture is rejected before persistence.

Run/import projections never authorize mutable event overwrites: one accepted invocation atomically appends the v2 run start and ordinal-1 attempt start; a legal next ordinal is explicit, sequential, idempotency-token bound, and pre-OA; source success forbids another attempt; a source failure either retries or terminalizes the run; an abort must retry. Joined deadline projections derive only when the v2 run terminal commits. The v2 run event/projection stores attempt count, never attempt identifiers. The rejected-source scheduling event is unique per retained rejection and deletes with that identity; no per-record deletion receipt survives.

Attention is projected as `map<AttentionCondition,set<attention_cause_key_sha256>>` from immutable `DOIAttentionEventV2` rows. The sole cause-key schema/domain is `doi-attention-cause-key/v2` / `doi-attention-cause-key/v2\n`; it binds exact case, condition, cause entity type/ID, applicable stream revision, and content hash, and contains no resolver field. SET stores that complete cause group and null resolution. CLEAR copies the exact cause group/key from the active SET, references that SET, and independently stores the complete resolution group/time/exact reason. The lifecycle wrapper references the typed v2 event and preserves the same values without another formula. CLEAR affects one exact active cause; a displayed condition clears only when its cause set is empty.

## 5. Exact retention and purge graph

`calendar90(anchor)` converts the instant to `America/New_York`, advances exactly 90 local dates preserving wall time, resolves a spring gap to the first valid local instant after the gap, chooses the later fall-overlap occurrence, and persists UTC together with retention-policy and timezone-database versions. Fixed elapsed-hour arithmetic is prohibited.

At case purge, one atomic transaction finalizes every current retained contribution and deletes: case/order identity; the complete v2 lifecycle stream, natural-key canonical bytes/hashes, case-source admission proof/binding, source bindings, payload bytes/hashes, full hashes, projection cache/hashes, and every nested prior-closure/retention binding plus its closure/projection/source/policy join indexes; case-owned work links; snapshots/lines/extraction attempts; evaluations/bindings/hashes/opportunities; Action Contexts/links; case-linked observations; all human/contact/DEDUPE/attention/WWC facts; interventions and every action/value/correction/reversal key, canonical payload, fingerprint, and source reference; exact resulting child Order Numbers, link keys/revisions/mappings; logs/caches/queues/errors/exports capable of reconstruction; and every other case-derived hash or join key. Attempt-owned staged/source-row detail has already been governed solely by TR-114 and is never retained as a case-lifecycle target.

The same case-purge transaction deletes each case-owned source-batch reference and any `RUN_WORK_GRAPH` run-identity reference, invokes TR-113, and re-evaluates due run last-reference deletion. A bare `DOICaseSourceBinding`/admission proof owns no run reference. Attempt-owned staged and due no-case rejection owners release under TR-114, with TR-105 executed only as that transaction's rejection-deletion subeffect. An immutable event containing `source_batch_id` deletes with its explicit owner graph and cannot outlive the corresponding reference. A zero-reference identifying batch or due zero-reference run is illegal.

For every closed source-import outcome, TR-114 applies at exact `calendar90(run.completed_at)`. One serializable transaction locks the closed attempt/run/batch/reference/aggregate graph; validates the policy/tzdb/deadline and all children; constructs and hashes one `DOISourceImportAttemptRetentionEventV1/SOURCE_IMPORT_ATTEMPT_PURGE_FINALIZED` with RC-114; increments the exact aggregate v2 row by one; deletes projection, v2 start/terminal events, ID/run link, ordinal/token/indexes, source workbook/tab/schema/actor/timestamps, failure/fingerprint/revision/range detail, staged/due-rejection/source-row refs, caches/logs/temp exports/files/backups/exceptions/dead letters and reverse lookups; releases attempt/staged/rejection-owned source-batch references through TR-113; separately releases the attempt's run-identity reference under TR-114; conditionally deletes the due last-reference run graph; and deletes the retention event itself. The event's payload/full domains and fixed hashes are exact in the source-retention and lifecycle registries. Failure at any step restores the complete pre-transaction state, including removal of the uncommitted aggregate delta. Repeated/concurrent purge after absence is a no-op and creates no tombstone/hash/receipt.

Only non-identifying daily KPI aggregate rows, the closed non-identifying `DOISourceImportAggregateV2` monthly outcome-count rows, and product-only relationship/revision knowledge may survive. A relationship survives only if it contains no originating order/case/context/source-row/evaluation/opportunity/intervention/result-order marker or reconstructable derivative. Removing a reverse link is insufficient when the payload itself encoded case identity.

No per-case purge receipt, tombstone, finalization marker, hash, or predecessor link survives. A post-purge per-order request is rejected transiently with `CASE_IDENTITY_NOT_RETAINED`, changes no aggregate, and persists no order-specific rejection.

## 6. Permanent OA safety and status

No entity stores an executable OA command, mutation URL, arbitrary request, click/type/fill/submit instruction, write credential/scope, host permission, session/cookie access, download/export/native/background authorization, page-script helper, computed mutation alias, or capability-elevation token. The v0.1.5 offline build has no OA-capable adapter and MUST pass the exact `DOI_OA_CAPABILITY_POLICY_v0.1.5.md` source/dependency/manifest/registry/built-output scan. A future adapter requires a separate frozen contract; side-effect uncertainty fails before dispatch.
